## 4. 覆盖率

| 文件          | 指标 | 实验前已有的 12 个用例 | 加上本实验的 21 个用例 |
| ------------- | ---- | ---------------------- | ---------------------- |
| `mermaid.ts`  | 语句 | 97.91%                 | 99.58%                 |
| `mermaid.ts`  | 分支 | 80.00%                 | 92.06%                 |
| `importer.ts` | 语句 | 100%                   | 100%                   |
| `importer.ts` | 分支 | 93.33%                 | 93.75%                 |

领域层 `src/core` 整体：语句 98.69%、分支 89.69%、函数 99.17%（门槛 80%）。

**分析**：实验前已有的用例语句覆盖率已近 98%，却一个缺陷也没有发现，因为它们只用了“正常”的输入。新用例主要提升的是分支覆盖率（80% → 92%），即每个判断的两种结果是否都测到了，这 7 个缺陷都出在“另一种结果”上。`mermaid.ts` 唯一未覆盖的一行是 `note` 形状的默认尺寸，Mermaid 中没有对应的记号，导入时不会出现。

## 5. 缺陷与修复

| 编号 | 发现用例 | 现象                                              | 原因                                      | 修复                                       |
| ---- | -------- | ------------------------------------------------- | ----------------------------------------- | ------------------------------------------ |
| B1   | E2       | `subgraph … end` 导入后多出一个名为 end 的节点    | end 一个词符合节点 id 的写法              | subgraph / end 作为结构语句跳过            |
| B2   | E5       | `graph TD;`、`A --> B;` 整行被跳过，方向也读错    | 分号不在任何规则里                        | 按引号与括号外的分号切分语句               |
| B3   | E6       | 普通文字（hello、world）也被导入成节点            | 没有检查是否出现过 graph / flowchart 声明 | 声明之前的语句一律跳过；补充省略方向的声明 |
| B4   | E7       | `A["x --> y"] --> B` 整行被跳过                   | 找连接器时没有跳过引号里的内容            | 只认引号与括号之外的连接器                 |
| B5   | R3       | 导出时写入的 `#quot;` 读回后原样留在文字里        | 导出转义了引号，导入没有还原              | 读入时还原 `#quot;` 与 `#数字;`            |
| B6   | R4       | 含竖线的连线标签导出后无法读回                    | 标签的正则不允许引号包住                  | 标签允许 `\|"a\|b"\|` 写法                 |
| B7   | R5       | 没有文字的节点导出后变成 process、decision 等文字 | 导出时用形状名顶替了空文字                | 空文字导出为 `""`，读回仍为空              |

修复提交：`6c0182d fix(io): 修复单元测试发现的 Mermaid 导入导出 7 个缺陷`。B3 在实验 6 准备演示时已经观察到，这次用测试确认并修复。

## 6. 测试驱动开发

需求来自实验 5：用 DiagramStudio 画 E-R 图时，`node.doc_id` 这种既是主键又是外键的字段只能标成 PK。

1. **先写测试**（`ea00d17`）：键位循环“无 → PK → FK → PK+FK → 无”；每一步同时给出 pk 和 fk 以便撤销；旧数据显示不变；按钮显示两个标记并提交切换后的值。运行结果 3 个失败（`keyLabel is not a function`、按钮只显示 PK）。
2. **补全代码**（`84a2729`）：修改 `nextKey`，新增 `keyLabel`，按钮在两个标记都有时上下两行显示。4 个测试全部通过。
3. **重构与检查**：键位格宽度不变，已有字段的显示与布局不受影响；全部 180 个单元测试通过。

过程中还发现测试环境不支持组件测试（`React is not defined`），先单独提交了 Vitest 的 JSX 配置（`60551ee`），使失败原因只剩功能本身。
